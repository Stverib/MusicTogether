# 真机能力验证

目的：在做任何产品代码之前，先确认 `docs/spec.md` §2 的三条假设在HarmonyOS 手机上是否成立。

## 怎么跑

手机和电脑连同一个 WiFi，在项目根目录起一个静态服务器：

    npx serve spike

或者用 Python：

    python -m http.server 8000 --directory spike

然后手机浏览器打开电脑的局域网地址，例如 `http://192.168.1.5:8000/verify.html`。

## 要记录的四件事

| 编号 | 测什么 | 通过标准 |
|------|--------|----------|
| R1 | 音频播放 | 测试音能响，进度条走到 3 秒结束 |
| R1b | 真实歌曲 | 选中本地 mp3 能播，能拖动进度条 |
| R2 | 选文件夹 | 弹出选择器能进到音乐目录，读出音频文件列表 |
| R3 | 后台存活 | 锁屏 15 秒 / 切 App 15 秒后回来，音频仍在播放且进度在走 |

## 结果怎么处理

- **R1 或 R3 不通过** → 纯网页方案要重新评估，回到 `docs/spec.md` §2。
- **仅 R2 不通过** → 不影响项目继续，只影响选歌的易用程度：退化为「多选文件」，
  功能完整，只是要一首首点。

## 已知的无关项

页面上「目录选择 API: 没有」是正常的 —— 那个 API（`showDirectoryPicker`）只有桌面
Chrome/Edge 才有，手机端本来就不支持，走的是 `webkitdirectory` 那条路。
